4 · Dependencies that are already clean

Everything inside v2/ — including all of the untracked paper_*.py — imports only v2.* and torch, numpy, scipy, pytorch3d, PIL, trimesh, plus flask for the viz and wandb optionally. The V1 leftovers at the repo root are the only code that pulls in anything else. In particular, the root-level utils/, models/, trainers/ and scripts/ are not imported by v2/ at all, and the v2/model.py comment chain that still says “PVConv” describes a layer that does not exist: there is no PVConv anywhere in v2/.

6 · Do not delete, even though it looks idle

  • v2/exps/vae_vx/frozen/ckpt_020000.pt — the prior's stats.pt keys its whitening cache on this exact path and step. Renaming or deduping it invalidates the cache and silently changes sampling.
  • stats.pt — holds pm, psd, gm, gsd plus a staleness key. Regenerating it changes the latent space the prior expects.
  • OccEncoder, FracHead, the keep head, and occ_smooth=3 — all three are load-bearing for grow, which is the paper's editing contribution.
  • sample_local_partitioned — the only way to sample above 4096 points, and the eval uses 16k/32k. Note the cfg==1.0 assertion: it silently constrains the guidance scale.
  • garment_mesh's b3x_lap15 preset — the viz exposes it and the paper uses both presets.
  • v2/viz/bodymodel.py's train-set coverage cache — used for in-distribution random masks, not just for bodies.

7 · Suggested removal order

  1. Zero risk, config only: delete --inp_patch_r/--inp_patches (already 0), --inp_seam_w (already 0) and --l1_plain (already 0) from train_prior.py/train_vae.py plus their guards. Then rebuild the configs; the numbers will not move.
  2. Zero risk, files: delete v2/tmp_*.py.
  3. Low risk: remove the unused hier_vd argument from the encoder branch and delete the enc_local='hier' branch in ClothEncoder (keep HierEncoder itself — the decoder and body tower use it), then re-instantiate and assert the VAE still reports 13.51 M parameters with zero missing/unexpected keys against frozen/ckpt_020000.pt.
  4. Low risk: drop fourier_enc from model.py, and kprox_proj plus the known_prox flag from prior.py — the checkpoint confirms both are absent, so this is a pure deletion.
  5. Medium risk: delete the known_mode='joint' path across prior.py and common.py. Requires that no shipped checkpoint was trained with joint; the shipped configs say clamp, so verify against pr_vx20_d512's config too.
  6. Housekeeping: the disk pass in §5, and a decision about the V1 tree at the repo root.

Every step above should end with the same two checks: python v2/run_pipeline.py --prior_exp pr_vx20_d512_ft_lr3e5 --prior_ckpt ckpt_020000.pt renders identically, and v2/eval_prior.py reproduces the 1-NNA numbers in the table. Seed-fixed sampling through viz/server.py is the fastest smoke test.
