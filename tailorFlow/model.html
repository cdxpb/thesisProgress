Overview

The full picture. Blue boxes hold learned weights that ship in a checkpoint; the VAE and the prior are trained separately. The single most important structural fact: the body enters only at decode time, so one sampled latent can be decoded on any body (body transfer) and any occupancy mask (trim / grow) without re-sampling the prior.

1 · The VAE

v2/model.py, ClothVAE + build_vae. A two-level latent point autoencoder (LION-descendant) whose latents are body-agnostic: the input garment is first transferred from the body it is worn on to a fixed canonical body, so the body never appears on the input side of the encoder.

Training rows (train_vae.py:augment)

Every batch mixes four row types over the CutDataset/EditAug coverage cuts (occ_edit=0.6, ramped over the first 1000 steps):

RowEncoder seesDecoder targetExtra signal
plainthe garmentthe garmentCD + EMD + L1 + edge + KL
unknown occ (30%)the garment, o = −1the garmentas plain — teaches unconditional decoding
trim (50% of cuts)the whole garmentthe garment cut to mask Akeep-head BCE; the clipped points get no CD/L1 — positions are pinned by the constant σpt instead
cut autoencode / growthe cut garmentthe cut / the full garment under full coveragegrows enter CD/EMD only, at grow_w=0.1

This row design is what makes coverage editing a data skill rather than a post-hoc trick: because dl=0 the point positions are nearly deterministic, so trimming is a pure selection problem for the keep head, and growing is a density problem the prior solves by inpainting.

Losses

loss = CD + EMD + 0.02·L1 + edge + 0.01·KL + 5·BCE(keep), with CD/EMD distance-weighted and trim rows excluded from the reconstruction average. Validation tracks CD/EMD/inside% per category, plus an own-body vs rolled-body pair and a latent-spacing ratio (run_xfer_val) that detects collapsed transfer.

2 · The prior

v2/prior.py + v2/train_prior.py. Two coupled rectified-flow models on the frozen VAE's whitened latents: GlobalPrior for z_g, then LocalPrior for the 4096×4 point block conditioned on z_g. Despite the name in the draft, there is no diffusion here.

What makes it a rectified flow, not a DDPM

CodeConsequence
Interpolantx_t = (1-t)·η + t·zstraight line; no noise schedule, no q(x_t|x_0)
Targetx_θ (clean latent), loss on v = (x_θ − x_t)/(1−t) against z − ηx-prediction; the sampler reconstructs v the same way
Denominatorflow_denom_min = 0.05clamp for the fat tail near t→1, where training and sampling must agree
Timestept ~ sigmoid(N(0,1)), plus 10% forced into [0.9,1.0] locallylogit-normal (SD3-style) + a tail emphasis for the local model
Couplingot_pair: exact Hungarian (linear_sum_assignment) on cdist, within each classrectified flow's OT-CFM coupling; ot_global=1 solves it over all ranks' batches, one problem per class
SamplerEuler or Heun, t = i/steps, 64 stepsan ODE solve; the final evals use heun at 64 steps
Guidancev = u + cfg·(v−u) with a null class token and a learned occupancy nullCFG is supported but cfg = 1.0 everywhere in the final runs

Correction to the draft's numbers: REPORT_OUTDATEDNESS_AND_RELATED_WORK.md §1.4 says the prior uses t_mode='logitnormal', ot_couple=1, cfg=2.0 and a separate occupancy CFG. In this checkpoint cfg is 1.0, there is no separate occupancy-guidance option anywhere in prior.py or train_prior.py, and ot_pair is Hungarian rather than a Sinkhorn/ ot_couple switch. inp_seam_w is 0.0 in the shipped config, so seam up-weighting is off.

The body-agnostic property is what allows the prior to be trained once and then decoded on any body. It is also why the encoder must transfer to the canonical body first: the prior models the distribution of canonical latents.

Fine-tuning stage (pr_vx20_d512_ft_lr3e5)

A 20k-step run at lr 3e-5 from pr_vx20_d512/ckpt_040000.pt. The width d = 512 (43 M local parameters) and occ_smooth = 3 were already set in the base run; the fine-tune changed inpaint_p 0.0→0.5, inp_seam_w 4→0, inp_patches 6→0, lr 2e-4→3e-5, steps 40000→20000, and turned in-training validation off (val 0). The learned FracHead predicts the fraction of the grown garment that is new cloth; the count of inpainting rows follows from it.

6 · What the code does that the 3DV draft does not say

These are the points where data/TailordiffReport/sec/03_method.tex and the v2 code disagree. The draft's equations 3–4 (DDPM, ε-prediction, πψ(z|c)), the z_o occupancy autoencoder, the PVConv / Body-PVConv layer, and the distance-field refinement module have no counterpart in the code at all.

DraftCode
Two latent DDPMs, ε-prediction, 1000 stepstwo rectified flows, x-prediction + velocity loss, minibatch-OT coupling, 64 Heun steps
Body-aware encoding through PVConv / body voxel branch in the encoderthe encoder is body-free: canonical-frame transfer, then a voxel U-Net on garment points only. The body is a decoder-side tower
Per-point latent h ∈ R^{N×D_h} with a feature channeldl = 0 — 3 numbers per slot, no feature channel, constant position σ
Occupancy edited through an MLP autoencoder on z_ono autoencoder; the mask is a conditioning signal and an edit operation on the vertices
Distance-field module with weighted kNN features and iterative projectionremoved. No DFNet, no refinement, no refine anywhere in v2/. Thin surfaces come from the keep head, the constant σpt, and screened-Poisson meshing with loop smoothing

On the method name. The generative half is a rectified flow, so Diff is now a misnomer; the draft defines \cloprior as TailorDiff in definitions.tex:26, so a rename is a one-line macro change. Note also that the shipped prior uses Euler/Heun ODE integration of an OT-coupled flow, which places it in the flow-matching / rectified-flow family, not in the “JiT” family — that term describes a transformer backbone, which is an orthogonal axis.

7 · The OT coupling, live

Everything else in this model is standard; ot_pair is the one place where the prior differs from a textbook flow-matching model. Noise and data are matched by an optimal-transport plan within each class, so the straight-line paths to the noise actually cross less. The panel below draws a 2-D caricature of exactly that: the same data and the same noise, coupled independently (left) or by OT (right).

Coupled with an entropic OT plan (Sinkhorn) — the shipped code solves the exact problem with Hungarian assignment instead, which is affordable at bs=32 across 4 ranks. The metric printed above is the mean squared path length of the coupling: OT makes the ensemble of straight lines shorter and more coherent, which is why the same network reaches a given quality in fewer steps.
